# 项目记录：完整数据查询链路实现

## 一、项目目标

本次项目的目标，是完整实现一套从数据库查询到前端展示的数据处理链路，主要包括以下环节：

1. 在 Mapper 层声明查询方法并编写 SQL，从数据库中获取原始数据；
2. 在 Service 层编写业务逻辑，对查询结果进行处理和计算；
3. 通过 Controller 层提供接口并返回处理后的数据；
4. 由前端发送请求，接收后端返回的数据，完成一次完整的前后端交互。

虽然本次需求的业务逻辑并不算特别复杂，但对当时还没有系统学习前后端交互流程的我来说，这是一次难度不小的尝试。能够依靠自己的摸索，一步一步打通整条链路，是本次项目中非常有意义的一次实践。

## 二、实现过程

### 1. Mapper 层：声明并查询数据库

项目首先从数据查询入手。在 Mapper 层声明数据库查询方法，并编写对应的 SQL 语句，从数据库中获取后续业务处理所需要的数据。

这一阶段让我初步理解了代码中的 Mapper 方法是如何与 SQL 对应起来的，也进一步认识了后端程序从数据库读取数据的基本过程。

### 2. Service 层：处理业务数据

完成基础查询后，下一步是在 Service 层实现核心的数据处理逻辑。具体流程如下：

1. 根据生产模块对应的名称，以及与其绑定的两个模块，在数据表中查询相应的时间信息；
2. 根据查询到的时间，判断并记录该条数据所属的月份；
3. 使用联表查询，通过 ID 在详细信息表中找到对应的合格数据和不合格数据；
4. 根据查询结果，计算每一条产线的合格率；
5. 将整理和计算后的结果返回给 Controller 层。

这部分是整条链路中业务逻辑最集中的环节。通过本次实践，我对 Service 层的作用有了更加具体的认识：它不仅负责接收 Mapper 查询到的数据，还承担着数据整理、业务判断、计算和结果封装等工作。

### 3. Controller 层：提供接口并返回结果

Service 层完成数据处理后，由 Controller 层提供对外接口。Controller 接收前端请求，调用 Service 中的业务方法，并将最终处理结果返回给前端。

通过这一过程，我逐渐理解了 Controller 在前后端交互中的位置：它是前端请求进入后端的入口，也是后端把处理结果返回给前端的出口。

### 4. 前端请求：打通完整链路

最后，由前端向 Controller 接口发送请求，后端依次完成 Controller 调用、Service 数据处理和 Mapper 数据查询，再将最终结果返回给前端。

至此，本次项目成功实现了以下完整流程：

> 前端发送请求 → Controller 接收请求 → Service 处理业务数据 → Mapper 查询数据库 → Service 计算各产线合格率 → Controller 返回结果 → 前端接收数据

这也是我第一次真正完成从数据库查询、后端处理到前端接收数据的完整链路。

## 三、与 Codex 协作的方法和收获

在完成项目的过程中，我也逐渐改进了自己与 Codex 对话和协作的方式。

我会根据已经完成的步骤逐步生成 Skills，并将整理好的完整 Skills 提交给 Codex。Codex 读取这些内容后，就能够理解之前已经完成的任务，并在已有进度的基础上继续协助我完成下一阶段的工作。

这种方法解决了任务推进过程中上下文容易丢失的问题，也让我学会了如何把一个较大的需求拆分成多个清晰的阶段，再逐步完成。虽然代码是在 Codex 的协助下一步一步实现的，但需求梳理、过程记录和持续推进本身，也是本次实践中的重要收获。

## 四、个人成长与感受

在开始这个项目之前，我完全不理解前端和后端之间是如何请求、调用、计算、处理并返回数据的。经过这次实践，我真正完成了一次从数据库到前端的完整数据链路，也对各层之间的职责和调用关系有了更直观的认识。

从一开始不知道如何连接前后端，到现在能够把 Mapper、Service、Controller 和前端请求串联起来，并实现数据查询、联表处理、合格率计算和结果返回，这个过程给我带来了很强的成就感。

这次经历也让我认识到，即使暂时没有系统学习过全部知识，只要能够拆分问题、记录步骤、不断验证，并合理使用工具辅助，也可以逐渐完成原本看起来很困难的任务。
